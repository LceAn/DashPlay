# 优化打磨记录（2026-11-06）

本 fork 的第三批维护打磨：每轮针对一个功能点，全部通过 658 个单元测试（Linux 容器），
仅剩 1 个基线即存在的环境性错误（容器 OpenSSL 3.5 对测试自制 CA 的严格校验，与代码无关）。

| 轮次 | 功能点 | 打磨内容 |
|---|---|---|
| R01 | mDNS 名称应答 | 应答循环每 2 秒醒来一次就 spawn 一次 `ip -4 -o addr`（常驻 0.5 fork/秒）；改为 30 秒刷新一次地址表，组播加入与应答不需要 2 秒级的新鲜度 |
| R02 | viewer 端口解析 | `resolve()` 每次读 2 个状态文件，而设置页每次渲染（配对期每 3 秒）要问它多次；加 stat 键（mtime_ns+size）缓存，命中零磁盘读 |
| R03 | setup/options 状态读取 | 页面与主控每次渲染重复读同一批 JSON 数十次；`setup_wizard` 新增 `_read_json`（stat 键缓存 + 返回 deepcopy，杜绝调用方别名污染），`load()`/`options()` 接入 |
| R04 | 在线手机指示灯 | 主控循环每 2 秒读 2 个状态文件只为决定 LED/回退标志；降为 5 秒，30 秒回退判定不受影响 |
| R05 | 设置页传输 | Handler 启用 HTTP/1.1 keep-alive（所有响应都带 Content-Length）：配对期每 3 秒整页刷新不再每次 TCP 握手 |
| R06 | 设置页异常兜底 | 渲染或操作抛错时连接被直接掐断且无响应；现回 500 页 + traceback 进 journal，车机浏览器总有回应 |
| R07 | 版本跳转 Host 校验 | 上一批的 token 白名单从 Handler 内联提炼为 `versions_redirect_allowed()` 方法，行为不变、可单测 |
| R08 | 版本管理页 | 同样启用 HTTP/1.1（页面 3 秒轮询 /api/status）；首页 PAGE 常量加 ETag/304，重复打开不再重传整页 |
| R09 | 有线 CarPlay TAP | `open_tap` 显式设 MTU 1500，与 tap_to_ncm 的 2048 读缓冲形成确定性关系——超 MTU 帧不再可能终结线程留下静默半桥 |
| R10 | 手机在位日志 | `note()` 的 19 行裁剪是无锁读-改-写，presence 多进程并发会互相吞行；加 `.lock` flock |
| R11 | OpenWrt 平台层命名 | 静态方法 `zone_input` 与模块级双参函数同名互相遮蔽（可读性陷阱）；方法改名 `zone_policy` 并注明委托关系 |
| R12 | F50 板级注释 | `stop_children` 注释写"每个 8 秒"而实现是共享 6 秒 deadline（实现是对的）；注释改为与实现一致 |
| R13 | 仓库卫生 | 上游把 8 个 `__pycache__/*.pyc` 提交进了版本库；加 `.gitignore` 并 `git rm --cached` 卸载跟踪 |
| R14 | 设置页防护测试 | 新增 3 个：note_check 去重表 70 个不同路径后 ≤64；Host 白名单（外部域名/非本机 IP/空 → 拒，dashplay.local → 放）；渲染抛错 → 500 |
| R15 | ap_ready 尾读测试 | 新增：日志追加 DISABLED/ENABLED 状态正确翻转；hostapd 重写日志（截断同 inode）后从头重读 |
| R16 | 探测节奏测试 | 新增：稳态连接 8 个 tick 内 `phone_station_address` 探测 ≤2 次（10 秒一次），转换期仍逐 tick |
| R17 | 版本页 ETag 测试 | 新增：首页响应带 ETag，If-None-Match 命中回 304 |
| R18 | 全量回归 | 658 个测试（本批新增 6 个）全部通过；期间抓住并修复 2 个测试暴露的问题（详见 git 历史） |
| R19 | 打磨记录 | 本文档：每轮一个功能点、一条可验证的改动理由 |
